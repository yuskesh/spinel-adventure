Spinel とは

  • 2026 年 4 月に RubyKaigi 2026 で Matz さんが公開した AOT コンパイラ
  • Ruby → C → ネイティブの実行ファイルで実行時に Ruby の VM もインタプリタも持たない
  • CRuby + YJIT の約 8.5 倍・interpreter の約 15.2 倍（最新の README）
  • 捨てたもの：文字列の eval・method_missing による呼び出し・実行時に名前が決まる define_method のように動かしてみるまで実行するコードや呼び先が決まらないもの
  • 使えるもの：send（呼び先の候補をビルド時に数え上げる）・Thread（公開時は未対応で今は GVL なしの並列）

この「捨てる」が旅全体の伏線

Spinel の AOT の道のり

① parselibprism で Ruby を読み AST を作る
② 全プログラムの型推論プログラム全体を見て値の型を決める
③ C の生成推論した型がそのまま C の型になる
④ ccC コンパイラがネイティブの実行ファイルにする
  • この順に 1 段ずつ見ていく：① 木を作る → ② 型を決める → ③ 型を C にする
  • 4 段は 1 つのプロセスで動き codegen は型推論の結果を直接使う
  • ② が Spinel の核：① は libprism・④ は普通の C コンパイラに任せ速いのも型をそのまま C の型にできるのも ② で型が決まるから

/* lib/spinel_rt.h (既定の --int-overflow=raise のとき) */
#define sp_int_add(a, b) ({                            \
    sp_int _sp_a = (a), _sp_b = (b), _sp_r;            \
    if (sp_int_add_overflow_p(_sp_a, _sp_b, &_sp_r))   \
